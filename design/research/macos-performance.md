# macOS performance (Outpost Gale on an M4 MacBook)

Researched 14 Nov 2026 (event day), web and source only, no engine runs. Engine: Godot 4.7.2-stable, Compatibility renderer, official macOS template (universal, ad-hoc signed by CI).
Sources are saved in `design/research/pages/macos/` (file names given below). **Verified** = seen in the 4.7.2 source, the 4.7 docs or our own code. **Reported** = an issue comment, forum post or benchmark, not checked by us.

Field result from the Mac (coordinator, 14 Nov): native `opengl3` 30 to 40 fps with stutter; `--rendering-driver opengl3_angle` 21 fps, dips to 8. The fps label showed the **Max** quality preset.

## TL;DR

The Mac was most likely running the **Max** preset, and that alone can explain most of the gap with the browser. Max renders the 3D at the window's full Retina pixel count with 8x MSAA, 4 shadow splits at 4096 and SSAO. Our code never picks Max by itself: on a desktop it picks Laptop. So someone chose Max on that Mac and `user://settings.cfg` kept it. The browser has its own `user://`, so it ran Laptop. Fix the preset first, then measure again before changing anything else.

## Q1: ANGLE on macOS

- **Backend: Metal.** Verified. In 4.7.2, `GLManagerANGLE_MacOS` asks EGL for `EGL_PLATFORM_ANGLE_TYPE_METAL_ANGLE` (`platform_macos_gl_manager_macos_angle.mm`). History (`gh_commits_gl_manager_macos_angle.json`): ANGLE over Metal arrived in 4.2 (#72831), was switched to ANGLE over OpenGL and made non-default in Dec 2023 (#85785: "using ANGLE over Metal on macOS was a total failure", it caused more issues than it fixed), then switched back to Metal in June 2025 (#107306, milestone 4.5, with godot-angle-static #17). The 4.7 class docs still say "over native OpenGL" for macOS; the source is newer than that line.
- **Default: native `opengl3`.** Verified (`main_main.cpp` line 2409; docs). `fallback_to_native` is on, so if ANGLE fails to start, native GL is used. In a virtual machine the engine forces ANGLE (#117371).
- **Does the official template ship ANGLE?** Verified indirectly: godot-build-scripts builds every macOS template with `angle_libs=/root/angle` from godot-angle-static (`godot-build-scripts_build-macos_build.sh`, `godot-build-scripts_build.sh`), and `detect.py` links `libANGLE.macos.<arch>` and defines `ANGLE_ENABLED` when that folder exists. The field test starting under `opengl3_angle` without an "ANGLE not available" error agrees.
- **`--rendering-driver opengl3_angle` on an exported build:** verified. The flag is parsed in release templates (`main_main.cpp` ~1331) and overrides the project setting. On a .app: `open OutpostGale.app --args --rendering-driver opengl3_angle`, or run `OutpostGale.app/Contents/MacOS/<binary>` with the flag.
- **Faster or smoother than native?** No public Godot benchmark found. What is known: native Apple GL is a deprecated layer over Metal; ANGLE is another layer over Metal, with GLES3 validation, transform feedback emulated by running the vertex shader twice (reported, ANGLE design notes), and the scene shaders translated to MSL. On the Windows side a maintainer said Godot's static ANGLE build ran worse than the system one (#72831 comment, cut off in the API reply). Upsides reported: V-Sync works under ANGLE (#79646 comment) and the macOS 26 popup hang does not happen (#111632). Our field test says it is slower for this game.
- **Shader caching under ANGLE:** verified. Godot hands ANGLE an `EGL_ANDROID_blob_cache` callback writing into the shader cache folder (`drivers_egl_egl_manager.cpp`), and the GLES3 cache uses GLES program binaries. So the second launch should compile less under ANGLE. Not enough to rescue it.

## Q2: Known Compatibility problems on macOS

- **Shader compile stutter.** Reported: OpenGL shader compiles on macOS are slow and there is "not much room to work around it" (clayjohn, #86731); one canvas case took 2 s on M1. The Godot docs say Compatibility has no ubershaders or pipeline precompilation, and the only cure is drawing every material, shader and particle once behind a cover (verified, `docs47_tutorials_performance_pipeline_compilations.rst`), which `HouseStyle.warm()` already does. A 4.7.2 measurement (#86731, Oct and Nov 2026) shows the scene shader compiles a default specialization nobody uses on first bind (about 5 programs per opaque material, 0.8 s each on WebGL); the fix, PR #124566 "Overhaul GLES3 shader compiler" (6 to 8x faster loads), is open and milestoned 4.9, so not in our 4.7.2.
- **Disk shader cache.** Verified mechanism: `rendering/shader_compiler/shader_cache/enabled` (default true) saves program binaries to `user://shader_cache`. Whether Apple's GL on Apple Silicon returns usable binaries is unknown; on Intel Macs it reported zero formats (reported). Godot handles zero-length binaries by compiling on use. Check the folder (TL;DR item 5).
- **GPU particles.** Reported, long-standing: transform feedback is on the CPU in Apple's GL driver; many emitters are slow (#54052, open, M1 to M3). Also a separate WebGL/ANGLE report: each GPUParticles3D process shader cost 22 to 25 s to compile on a cold Windows ANGLE load (#87843), fixed by converting to CPUParticles3D.
- **MSAA.** Supported for 3D (verified docs table). No macOS-specific bug found; its cost scales with pixels, which is the Max preset problem.
- **Glow, shadow maps, ReflectionProbe, OmniLights.** No macOS-specific Compatibility bug found. General limits (verified, renderers table): 8 omni and 8 spot per mesh, 2 reflection probes per mesh in Compatibility. Shadowed lights are drawn in an extra pass in sRGB space (verified, lights_and_shadows doc "Note on Appearance Changes"), so every shadowed lamp costs a pass.
- **V-Sync / ProMotion.** Reported: native GL V-Sync runs at twice the refresh rate (#79646, open, last confirmed macOS 26.2 + 4.5.1); stutter on the built-in display with an external monitor attached (#74523, open; the reporter blames V-Sync on a non-60 Hz setup). Godot sets V-Sync with `kCGLCPSwapInterval` (verified, `platform_macos_gl_manager_macos_legacy.mm`). An M4 MacBook Pro has a 120 Hz ProMotion panel; an M4 Air is 60 Hz. No Godot data on ProMotion with Compatibility; a 30 to 40 fps game on a 120 Hz V-Synced display alternates 3 and 4 refreshes per frame, which reads as judder (our inference). Capping at 30 or 60 makes it even.
- **`display/high_res`** (our preset: true). Verified: sets `NSHighResolutionCapable` and asks GL for the full Retina surface. With it off, the window renders at half the pixels per axis and macOS upscales everything, the HUD too (blurry text). Keep it on; the pixel budget already handles the 3D.
- **macOS 26 popup hang** (~500 ms when a window is created, Compatibility native only) was fixed in 4.6 (#111632, #111657). Not ours.
- **Low Power Mode** limits performance on battery (verified, Apple support page). App Nap and occlusion affect only hidden windows.

## Q3: Only macOS on Metal (Forward+ or Mobile)

- **Viable, one line.** Verified: Metal is the default RenderingDevice driver on macOS arm64 (`driver.macos="metal"`), it is in the official template, and Intel Macs fall back to Vulkan/MoltenVK, then to OpenGL (`fallback_to_opengl3`, verified in `display_server_macos.mm`). A per-platform override `renderer/rendering_method.macos="mobile"` keeps every other platform on Compatibility. Prefer **Mobile** over Forward+: closest feature set to Compatibility, cheaper.
- **What our code already handles:** `HouseStyle._shadowed()` returns the energy unchanged when the method is not `gl_compatibility` (verified, `house_style.gd` line 507), so the 2.2x sun correction switches itself off. No shader uses `CURRENT_RENDERER`, screen or depth textures; the sky shader only reads `SCREEN_UV` for dither. Godot shading language is the same across renderers, so `sky.gdshader`, `surface.gdshader`, `terrain.gdshader` should compile.
- **What will look different (verify by eye):**
  - Light: Mobile adds lights in linear space in one pass, Compatibility adds shadowed lights in sRGB after tone mapping. The palette was tuned under the correction, so darker roles come out a little different.
  - `surface.gdshader` glass: `SPECULAR 0.225` and the `ALPHA^2.2` dust coat were tuned to Compatibility's environment BRDF fit and sRGB blending (comments in the shader). Expect glass and dust coats to read differently.
  - Glow and fog: same knobs, different implementation; check glow 0.4.
  - SSAO: Mobile has none (Max's `ssao` does nothing there). Reflection probes: up to 8 per mesh instead of 2, so probe blending changes where boxes overlap.
  - Sky ambient: our rig uses a colour ambient, which behaves the same.
- **Shader compile on Metal:** Forward+/Mobile have ubershaders and pipeline precompilation, so in-play stutter should mostly go (verified docs). The shader baker would remove the first-launch compile, but it needs a macOS editor with Xcode and does not run with `--headless`, so our Linux CI cannot bake (verified docs). First launch on Metal takes several seconds longer (bruvzg: "around 10 sec" for the project manager, reported #115635). Risk: #123481 (open) shows a Metal pipeline compile taking minutes on M4/M5 under macOS 26 for a custom shader with many texture samples in a loop (reported; Apple's compiler, cached after the first success). Our terrain and surface shaders sample several detail textures, so watch the first launch.
- **Also fixes:** GPU particles run on compute, no transform feedback stall. V-Sync goes through Metal, which does not have the doubled-rate bug (#79646 says Forward+ and Mobile lock correctly).
- **Effort:** 5 minutes to test from the command line on the Mac (TL;DR 2). If adopted: one line in `project.godot`, 1 to 3 hours of look review. The look can be previewed today on Linux with `--rendering-method mobile` (Vulkan), once the laptop's GPU is free, since Mobile on Vulkan and on Metal share the renderer. Tests that assume Compatibility only run on Linux and stay as they are.

## Q4: Other things Godot developers do

- Keep `application/app_category` = Games (default, verified) and play **full screen** so macOS can enable Game Mode (reported trigger). `GCSupportsGameMode` can be added through the export option `application/additional_plist_content` (verified option exists) if Game Mode does not engage; reports are mixed.
- Cap the frame rate on a 120 Hz screen (our `maxFps` knob) instead of letting V-Sync divide unevenly.
- Use CPU particles on macOS when staying on Compatibility (Godot maintainers suggested converting at run time on macOS, #54052).
- `run/low_processor_mode`: for tools and menus, not games (verified docs). Skip.
- Nothing in the macOS export preset changes GPU speed: `binary_format/architecture="universal"` runs native arm64 on an M4; `texture_format/s3tc_bptc` is what desktop GPUs read (Apple Silicon also reads ETC2/ASTC); both are already on.
